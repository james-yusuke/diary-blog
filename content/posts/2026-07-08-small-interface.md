インターフェースは、先回りして作るものではなく、依存の向きを整えるために作るものだと考えています。

最初から万能な抽象化を置くと、実装よりも説明が増えます。反対に、具体的な型だけで進めると、外部との接点が曖昧なまま育ってしまうことがあります。

## 呼び出す側が欲しい形を置く

Goでは、インターフェースを実装する側ではなく使う側のパッケージに置くと、必要なメソッドだけが残りやすくなります。

```go
type PostFinder interface {
  Find(slug string) (Post, bool)
}
```

ここで大事なのは、今使わない操作を並べないことです。境界は小さいほど、あとから変更する余白を残せます。

> 良い抽象化は、未来を当てることではなく、変更の理由を一か所に集めること。

一度書いたインターフェースも、役目がなくなれば消してよい。小さく始めるのは、慎重さではなく速度のためです。
